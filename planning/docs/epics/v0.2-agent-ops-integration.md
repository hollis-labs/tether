# Epic v0.2: Agent Ops Integration

**Status:** later
**Goal:** Consume resolved agent/skill/tool/prompt assets from Agent Ops without absorbing asset-management responsibilities into Agent Mux. Support installer adapters, local/global/project scope resolution, and import/export across multiple agent ecosystems (NANITE.md, CLAUDE.md family, AGENTS.md, etc.).
**Theme:** Clean runtime-vs-asset separation. Agent Mux runs sessions; Agent Ops installs and resolves capabilities.
**Dependencies:** v0.1 Operational Agents
**Exit criteria:**
- [ ] An "asset reference" model exists in Agent Mux storage that points at Agent Ops–managed assets (id + type + source + version + scope + compatibility metadata).
- [ ] The launch resolver accepts resolved asset references from Agent Ops and materializes them into boot prompts / tool configs.
- [ ] Installer adapter contract is defined and one reference adapter is implemented.
- [ ] Local / global / project scope resolution works end-to-end through an Agent Ops lookup API.
- [ ] Import/export across at least two agent ecosystem formats is demonstrated.
- [ ] Agent Mux does not own any installer, registry, or catalog logic — only the reference/consume side.

## Motivation

Context-pack §09 is explicit: "Agent Mux should not become the owner of agent-system installation formats. However, Agent Mux must be designed to consume resolved assets that Agent Ops manages." The current catalog (`examples/catalog/`) is a v0.0.1 convenience — not the future shape. v0.2 is where the split becomes real: Agent Ops owns install/update/uninstall/registry/format-adapter, and Agent Mux consumes resolved references.

The architectural payoff: Agent Mux stops being tied to a single file layout. Assets can come from Nanite-formatted directories, Claude-Code agent specs, AGENTS.md layouts, or future ecosystem conventions — the runtime doesn't care as long as Agent Ops can resolve them.

## Scope

### In
- CapabilityAsset / AssetReference model on the Agent Mux side.
- Lookup client contract for Agent Ops (search / resolve / compatibility-check).
- Installer adapter contract (interface only — implementations are Agent Ops's concern).
- Scope resolution in the launch resolver (local overrides global overrides project, or as Agent Ops defines).
- At least one reference adapter demonstrating multi-ecosystem import/export.

### Out (deferred to v0.3+)
- Registry UI / catalog browsing (Agent Ops's concern).
- Cross-ecosystem format *authoring* in Agent Mux (deliberately out — Agent Ops owns this).
- Rich TUI/GUI for asset browsing from the mux side (v0.3+).

## Candidate sprints (not yet broken out into files)

- **v020-01 — Asset Reference Model** — add tables/types for resolved asset references; evolve launch resolver to consume them alongside inline configs.
- **v020-02 — Agent Ops Lookup Client** — define client interface in `internal/agentops` (or similar); stub implementation; integration hook in resolver.
- **v020-03 — Installer Adapter Contract** — define Go interface (install / uninstall / update / verify); document as an ADR; provide reference adapter.
- **v020-04 — Scope Resolution** — local / global / project precedence; config model updates; resolver integration.
- **v020-05 — Cross-Ecosystem Round-Trip** — import a NANITE.md-style agent; launch it via mux; re-export as a CLAUDE.md-family definition (or equivalent).

## Review / readiness notes

- **Agent Ops is a separate system** that does not live in this repo. v0.2 cannot start in earnest until Agent Ops has a lookup contract of some kind. If Agent Ops work slips, v0.2 slips. Watch for this.
- **Avoid pulling logic across the boundary.** The anti-goal in §10 ("do not turn Agent Mux into Agent Ops") is worth repeating here. Every task in this epic should have a scope fence saying "no installer logic in mux."
- **NANITE.md / CLAUDE.md / AGENTS.md** format specifics need mapping before the cross-ecosystem round-trip sprint is actionable. Capture as a readiness gap when that sprint is broken out.
- **Back-compat with v0.0.1 YAML catalog:** the existing `examples/catalog/` should still work (probably as one resolver path among many). Sprint v020-01 must preserve it rather than delete it.
- Sprint files deferred until v0.1 ships and Agent Ops's contract is visible.
