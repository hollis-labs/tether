# Epic v0.0.4 — Dogfood-Ready Infrastructure

**Status:** next
**Created:** 2026-04-19 (reframe from v0.0.3 TUI MVP remainder)

## One-line theme

When v0.0.4 ships, `mux` is dogfood-grade for the "run and manage coding-agent sessions" workbench use case. Everything after v0.0.4 is polish.

## Why this version exists

v0.0.3 Sprint 1–2 delivered a working TUI that can browse catalog + launch + attach. Smoke testing revealed the gap: attach works for shell-like providers but renders poorly for full-screen TUI providers (notably `claude` CLI) because PTY-size propagation and ANSI handling are missing. There's also no sandboxing enforcement today — the schema has `AgentPermissions.Network` and `AgentPermissions.DefaultSandbox` but neither is wired into the launch path.

User feedback (2026-04-19): *"My focus would be on getting to the point where the PTY and attach/detach, sandboxing, all that works really well. Once it's stable in that regard, we can start dogfooding those aspects while we work on CRUD, TUI, etc. After that, everything is gravy."*

This epic re-orders v0.0.3's unshipped remainder (Sprints 3–6) to v0.1 and introduces the infrastructure that makes the daemon + TUI actually usable for day-to-day dogfooding.

## Exit criteria

1. `mux tui` attach panel renders full-screen TUI providers (e.g., `claude` CLI) at the correct terminal size — no cursor corruption, no jumbled output on resize.
2. An "open in external terminal" action on attach-capable screens launches `mux sessions attach` in a separate terminal window — as a reliable fallback for any rendering edge case.
3. Session-lifecycle edges are audited and hardened: daemon-crash recovery leaves no orphans; SIGKILL parent reaps children; attach-count stays correct under churn; abandoned workspaces are reclaimable.
4. `AgentPermissions.Network` and `AgentPermissions.DefaultSandbox` are enforced at launch on macOS (primary platform). Linux gets a best-effort path or a documented skip.
5. Checkpoint resume is wired end-to-end: a session can be checkpointed, stopped, and resumed into a new runtime with the prompt context restored.
6. Launch wizard supports ephemeral launches (try-once, no save), save-and-launch, and save-only exits — the ergonomic launch path for experimentation.
7. Roadmap, ADRs, and boot prompt reflect the reframe.

## Anti-goals (carry-over from context pack §10)

- Do NOT turn Agent Mux into Clockwork (planning/orchestration).
- Do NOT turn Agent Mux into Nanite (chat UX).
- Do NOT embed memory logic that belongs in Vanta.
- Do NOT build a GUI first.
- Do NOT couple the runtime to one vendor SDK.

## Version-specific anti-goals

- Do NOT pull forward the full parked Integration Foundation — only checkpoint resume unparkss.
- Do NOT design a cross-platform sandbox before macOS works. Linux is best-effort for v0.0.4.
- Do NOT build a full in-TUI terminal emulator for attach rendering. The external-terminal escape hatch is the reliable path for v0.0.4; true in-TUI ANSI fidelity is a later concern.

## Invariants from earlier versions that must hold

- **ADR 0006** — Provider contract is stable; additive changes only.
- **ADR 0010** — Local API typed error envelope.
- **ADR 0011** — Attach is octet-stream, not SSE.

## Dogfood criteria (definition of "done enough to start dogfooding")

After v0.0.4 ships, the user should be able to:

- [ ] Launch a `claude` CLI session from the TUI and see it rendered natively as a chat surface — no ANSI/rendering fragility, tool_use blocks visible, token usage live.
- [ ] Continue a prior `claude` conversation via `--resume` without manual session-id juggling.
- [ ] Launch a shell-based session (bash, vim, htop) and have it render correctly on terminal resize in the PTY attach panel, OR drop into a raw external terminal via F2 for pixel-perfect rendering.
- [ ] Detach from a session, do other work, re-attach without data loss.
- [ ] Run a session that is sandboxed away from the rest of the filesystem.
- [ ] Stop/start the daemon without losing session history or orphaning child processes.
- [ ] Resume a stopped session from an agent-mux checkpoint (separate from claude's built-in resume).
- [ ] Launch an ad-hoc session without authoring a full launch profile YAML first.

When every box above is checked on a real user workflow, the epic is done.

## Ecosystem footprint (new in this version)

`pkg/claudestream/` is the next extractable Go package. The portfolio already has `framework/libs/go-directives`, `go-mcp`, `go-otel`, `go-plugin`, `go-providers`, `go-queue`, `go-toolbroker`, and `plugin-sdk`. The plan for claudestream follows the same trajectory:

1. Copy Nanite's parsers into agent-mux's `pkg/claudestream/` (Sprint 2 T-01) with attribution.
2. Iterate in-place through Sprint 2's tasks — agent-mux is the validating consumer.
3. When stable, promote to `framework/libs/go-claudestream` (or similar).
4. Nanite migrates to consume the promoted package instead of maintaining its own copy.

Every `pkg/claudestream/*` commit must preserve extractability: no `internal/` imports, no agent-mux-specific naming in the public API, README documents the promotion target explicitly.
