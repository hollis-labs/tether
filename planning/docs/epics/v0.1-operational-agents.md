# Epic v0.1: Session Routing + Provider Surface

**Status:** next
**Goal:** Make Agent Mux a clean opt-in provider/session substrate for Clockwork, Nanite, and other systems: it creates and manages session environments, routes messages, exposes attach/resume/events, and provides agents to clients without owning their orchestration or execution policy.
**Theme:** Shared session substrate, message routing, provider abstraction, consumer-friendly connectivity.
**Dependencies:** v0.0.4 Dogfood-Ready Infrastructure and v0.0.5 MCP + Provider Integration. Checkpoint resume, go-messaging, MCP stdio, MCP proxy aggregation, opencode provider, and tool-call observability are now shipped or stabilizing; v0.1 should turn those into stable opt-in contracts.
**Exit criteria:**
- [ ] Clockwork can choose Mux as one provider/session route for tasks while retaining the ability to execute through direct providers.
- [ ] Mux-managed sessions expose stable launch, message, attach, observe, checkpoint/resume, and abort contracts without encoding Clockwork policy.
- [ ] Message routing semantics are stable: addressing, request/reply, correlation, inbox/thread, consume/cancel, and durable history.
- [ ] Session, message, and tool-call events are observable/queryable for clients, without Mux deciding scheduling, retry, PR, close, or escalation policy.
- [ ] Nanite's Mux plugin has a clear consumer contract for session connectivity and conversational access to Mux-managed agents.
- [ ] Vanta context can be consumed for boot/resume context without making Mux the memory system.

## Motivation

Context-pack §04 Use Cases 4–7 describe operational agents: warm knowledge keeper, Clockwork project manager, architecture ideation partner, content ideation partner. Those use cases still matter, but the shipped MCP/provider work changes the right boundary.

As of 2026-04-22, Clockwork can already boot tasks and execute work. It may do that through its built-in scheduler/runner and direct providers, or it may choose Mux as a provider/session substrate when it wants Mux-managed environments, routing, messaging, attach/resume, and deeper session integration. Clockwork owns the orchestrator agents that pull sprints, dispatch workers, run review agents, create PRs, close tickets, escalate blockers, and queue runnable work.

Nanite is also building its Mux plugin, which opens the Nanite connectivity layer to Mux-managed sessions and tools. Agent Mux now has the primitives both streams can consume: durable session ownership, checkpoint resume, go-messaging, MCP-native mux tools, MCP proxy aggregation, tool-call observability, and opencode/claude provider adapters.

The architectural payoff is sharper now: "Clockwork executes and orchestrates / Agent Mux provides opt-in sessions and routing / Nanite connects and interacts / Vanta informs." v0.1 should prove that split by stabilizing common contracts and protocols, not by making apps depend on each other.

## Scope

### In
- Provider/session contract for clients that choose Mux: launch profile, boot payload, returned durable IDs, provider hints, session continuity, workspace/env metadata.
- Message routing contract: address forms, request/reply, correlation, inbox/thread, consume/cancel, durable history, and client identity.
- Client observation contract: session lifecycle, attach/read output, message events, tool-call events, checkpoint/resume events, and terminal outcomes.
- Runtime health signals: process alive, last output time, last tool-call time, provider turn state, exit code, checkpoint availability. Clients decide policy from these signals.
- Vanta context injection for boot/resume/orchestrator prompts, scoped to user/project/session preferences and decisions.
- Consumer contract for Nanite's Mux plugin: session list/detail, attach/event stream, message/request/reply, launch/resume/abort, and tool discovery.
- Minimal TUI fixes that unblock session/routing dogfooding, especially event feed correctness and noisy all-view cleanup.

### Out (deferred to v0.2+)
- Agent Ops asset/catalog resolution and installer logic (v0.2).
- Cross-ecosystem import/export of agent definitions (v0.2).
- Full Nanite GUI control plane (v0.3+, unless pulled forward on the Nanite side through the Mux plugin).
- Rich workflow visualization and dashboards (v0.3+).
- Clockwork orchestration/execution policy: sprint pulling, worker sequencing, dependency DAGs, budgets, retries, review agents, PR creation, ticket closing, and escalation.
- Treating Mux as Clockwork's only execution path. Mux is one provider/session option, not a required dependency.

## Candidate sprints (not yet broken out into files)

- **v010-01 — Provider/Session Contract** — define the stable contract clients use when they choose Mux: launch profile, boot payload, durable IDs, provider hints, workspace/env metadata, terminal outcome, and error shape.
- **v010-02 — Message Routing Contract** — harden go-messaging semantics for multi-agent use: address URNs, request/reply, correlation IDs, inbox/thread history, consume/cancel, and race-free read behavior.
- **v010-03 — Client Observation Surface** — make session lifecycle, attach/read output, messages, tool calls, checkpoints, and terminal outcomes observable/queryable without turning those signals into Clockwork policy.
- **v010-04 — Runtime Health Signals** — expose raw signals clients need for their own stall/escalation policy: process alive, last output/tool-call time, provider turn state, exit code, checkpoint availability, and heartbeat where applicable.
- **v010-05 — Vanta Context Injection** — resolve user/project/session memory scopes and inject concise preference/decision context into boot and resume prompts.
- **v010-06 — Nanite Plugin Consumer Contract** — lock the API/MCP/SSE surface Nanite's Mux plugin needs: list sessions, observe events, attach/read output, send messages, launch/resume/abort, inspect tool availability, and map Mux identities into Nanite session UX.
- **v010-07 — TUI Dogfood Fixes** — fix session/routing-critical TUI issues only: activity feed source, all-view noise, confusing runtime labels, and root model routing tests before further UI expansion.

## Review / readiness notes

- **Clockwork is a client/provider consumer, not a dependency.** Review active Clockwork tasks before breaking sprint files, but keep Mux scope to shared protocols and session/routing capabilities. Clockwork owns task execution and can bypass Mux with direct providers when appropriate.
- **Nanite's Mux plugin is a peer consumer.** Treat its requirements as first-class alongside Clockwork's provider/session needs. The plugin should consume Mux connectivity; Mux should not absorb Nanite's chat/session UX.
- **Keep the boundary sharp.** Mux creates/manages environments and sessions, routes messages, exposes events, and provides agents to other systems. Clockwork owns planning, dependency DAGs, task transitions, budgets, queueing, review agents, PR/close/escalation, and execution policy.
- **Provider neutrality is the quality bar.** Opencode is useful, but every v0.1 task should be phrased in shared provider/session verbs unless it is explicitly adapter work.
- **Event durability needs a decision.** Phase 2 MCP proxy observability used in-memory event storage. v0.1 needs to decide what is persisted, what is live-only, and which query surfaces clients can rely on.
- **Vanta integration mode remains unresolved.** Prefer service-backed lookup first; embedded library mode is a later optimization unless latency or availability forces it.
- **Hot/cold policy is demoted.** It remains useful, but routing/session contracts can land before a full warm-agent lifecycle model. Reintroduce hot/cold once client needs prove the semantics.
- **TUI work is tactical.** Fix visibility and correctness issues that block session/routing dogfooding; leave richer UX and visual workflow design for v0.3+ or Nanite.
