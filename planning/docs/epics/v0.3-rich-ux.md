# Epic v0.3+: Rich UX & Advanced Orchestration

**Status:** deferred
**Goal:** Layer richer human-facing surfaces on top of the stable runtime/API established in v0.0.2–v0.2. Richer TUI, optional desktop GUI, workflow visualization, multiplexor flows, observability dashboards, and proper service-manager integration with Cerberus.
**Theme:** Rich UX, advanced orchestration, observability, service-manager integration.
**Dependencies:** v0.2 Agent Ops Integration
**Exit criteria:** (deliberately loose — v0.3 is a theme bucket until prior versions land)
- [ ] The runtime can be supervised as a proper local service via Cerberus (plist/service install, dev supervision, lifecycle hooks).
- [ ] A richer TUI and/or desktop GUI is available for live session browsing and attach/detach.
- [ ] Workflow visualization (multi-session groups, broker envelopes, handoffs) is observable.
- [ ] Multiplexor flows (one primary, several siblings) are a first-class UX pattern.
- [ ] Background agents with brokered collaboration can be dashboarded.

## Motivation

Context-pack §03 explicitly defers rich UX to v0.3+: "richer TUI, optional desktop GUI, workflow visualization, multiplexor flows, background agents with brokered collaboration, observability dashboards, better service-manager integration with Cerberus." Context-pack §01 reinforces the design rule: "The UI is always a client of the runtime, never the source of runtime truth" — so the only responsible order is runtime first (v0.0.2–v0.2), UX after.

This epic is a capture bucket for themes, not a plan. Its sprints will be broken out once v0.2 lands and the runtime+asset story is stable.

## Scope

### Themes in
- Richer TUI (likely reusing Nanite components or a dedicated mux TUI).
- Optional desktop GUI.
- Workflow visualization: swimlanes, message flows, handoff timelines.
- Multiplexor flow UX: one-primary-many-siblings pattern as first-class.
- Background-agent dashboards.
- Observability: logs, metrics, traces, session health roll-ups.
- Cerberus integration: plist/service installs, dev-server supervision pattern reuse, lifecycle hooks.

### Out (never)
- Anything that reasserts the UI as the source of runtime truth.
- GUI-first feature work that smears runtime logic into the UI layer.
- Replacing Nanite (Nanite is the interactive UX; this epic complements it, doesn't compete).

## Candidate sprints (not yet broken out into files)

- **v030-01 — Richer TUI** — live session list, attach panel, input pane, event stream view; reuse Nanite components or build native.
- **v030-02 — Desktop GUI (optional)** — evaluate + prototype; decide whether this belongs in mux or in Nanite.
- **v030-03 — Workflow Visualization** — render multi-session groups and broker envelope flows.
- **v030-04 — Multiplexor Flow UX** — first-class pattern for one-primary + N-siblings coordination.
- **v030-05 — Background Agent Dashboards** — observability for warm agents + scheduled work.
- **v030-06 — Observability Stack** — structured logs, metrics exporter, optional OTel traces.
- **v030-07 — Cerberus Integration** — service install, dev supervision, lifecycle hooks.

## Review / readiness notes

- **Sequencing:** nothing in v0.3+ is actionable until v0.0.2 (shipped), v0.0.3 TUI MVP, v0.1, and v0.2 each exist and are stable enough that a UX layer on top is worth building. The Integration Foundation work (parked) may also need to land first depending on which v0.3+ themes are pulled in.
- **Overlap with Nanite:** richer TUI + desktop GUI both overlap with Nanite's remit. Before any of these sprints start, do a "what belongs in Nanite vs what belongs in mux" pass. The safe default is: if it's human conversational UX, it's Nanite; if it's runtime/ops observability, it's mux.
- **Cerberus sequencing:** Cerberus is itself a separate evolving system. Integration task depth depends on Cerberus's maturity at the time. Likely a v0.3 or later concern.
- Sprint files deferred until v0.2 ships.
