# Epic v0.0.1: Foundation (retrospective)

**Status:** shipped
**Goal:** Ship a rough-but-functional Go CLI that loads YAML configs, resolves a launch plan, creates a session workspace, launches a provider command in a PTY, and tracks sessions in SQLite. Establish clean package boundaries (config / launch / workspace / provider / session / store) consumed by a thin CLI through a single service facade.
**Theme:** Local-first runtime substrate, agent-first architecture from day one.
**Dependencies:** none
**Exit criteria:**
- [x] `mux projects list`, `mux agents list`, `mux resolve`, `mux launch`, `mux sessions list|get|tail` all work against an example catalog.
- [x] End-to-end smoke test: `launch` creates a workspace, starts a PTY child, persists a row in SQLite, transitions states through `launching → running → completed`.
- [x] Config / launch / workspace / provider / session / store packages each have passing unit tests where the behavior is important (loader, resolver, workspace layout, store CRUD).
- [x] No TUI, no HTTP API, no broker, no MCP — strictly the launcher foundation.

## Motivation

Before layering daemon/runtime ownership, attach/detach, checkpoints, brokering, and a local API onto Agent Mux, the project needed a clean skeleton with the right seams. The v0.0.1 theme is "prove the shape is viable." Context-pack §06 confirms: "The project already separates config/catalog, launch, workspace, provider, store, session, and app service concerns. The current shape is viable as the seed of a durable runtime/control plane."

The payoff: v0.0.2 does not need a rewrite — it evolves what's here.

## Scope

### In
- Cobra CLI (`cmd/mux`) as the only client surface.
- YAML catalog loader with typed models for global / projects / agents / providers / launches.
- Launch resolver producing an inspectable `launch.Plan` (JSON-serializable).
- Boot prompt composition from layered fragments.
- Workspace materializer (per-session dir tree with `inbox / execution / scratch / artifacts / prompts / state / logs`).
- `provider.Adapter` interface + single `claudecode.Adapter`.
- PTY runtime (`session.Start` / `Wait` / `Kill` / `Attach`).
- SQLite store via `modernc.org/sqlite` (pure Go, no CGO) with `sessions`, `launch_plans`, `events` tables.
- Application service facade (`internal/app.Service`) wiring all of the above.

### Out
- TUI, HTTP API, MCP adapter, sandbox execution, broker/messaging, workflows/parallel sessions, desktop GUI, full asset-system adapters.

## Known limitations carried forward into v0.0.2

These are the things v0.0.2 must address. Each corresponds to a v0.0.2 sprint:

1. **One-shot CLI runtime.** Each `mux …` invocation builds fresh state. Live ownership of running sessions lives only in the invoking process — subsequent invocations cannot attach to sessions they didn't start. → [Sprint v002-01](../sprints/v002-01-daemon-runtime.md).
2. **Snapshot-only Attach.** `session.Handle.Attach` copies the log file once and returns; there is no tail-follow, no live PTY stream, no multi-client fan-out, no SendInput. → [Sprint v002-02](../sprints/v002-02-live-attach-input.md).
3. **Env replacement.** The `claudecode` adapter replaces the entire child environment with `plan.Env` rather than merging passthrough + overrides over the inherited base. → [Sprint v002-04](../sprints/v002-04-provider-contract.md).
4. **Unsynchronized maps.** `app.Service.running` (and the later `killing` concept) are plain `map[string]*session.Handle` accessed from multiple goroutines without locks. Noted in commit `d2383c0`. → [Sprint v002-01](../sprints/v002-01-daemon-runtime.md).
5. **No LogicalAgent split.** `sessions` table stores `agent_id` directly; there is no durable logical-agent identity separate from ephemeral runtime session. → [Sprint v002-03](../sprints/v002-03-storage-evolution.md).
6. **No API boundary.** The CLI reaches into `app.Service` directly. Nanite/Clockwork have nothing to call. → [Sprint v002-05](../sprints/v002-05-local-api.md).
7. **No event bus.** `store.events` is append-only for debugging but there is no runtime pub/sub. → [Sprint v002-06](../sprints/v002-06-eventing.md).
