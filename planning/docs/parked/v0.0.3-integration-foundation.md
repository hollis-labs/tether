# Epic [Parked]: Integration Foundation

**Status:** parked (2026-04-19) — originally slotted as v0.0.3. External client work (Nanite, Clockwork) deferred until consumer teams signal readiness; the internal items (API provider, checkpoint resume, mailbox semantics) pause with them to preserve epic coherence. Unpark as a dedicated release slot when revived — do not silently fold individual sprints into another version without an explicit decision.
**Goal:** Make Agent Mux useful to other systems in the stack. Nanite can discover and attach to sessions. Clockwork can launch, inspect, and dispatch through the local API. A first concrete API-backed provider exists. The checkpoint model supports an end-to-end resume path. The broker supports request/reply semantics with correlation IDs.
**Theme:** Clean integration with Nanite, Clockwork, and at least one non-CLI provider; detached interactive sessions behave predictably.
**Dependencies:** v0.0.2 Runtime Foundation
**Exit criteria:**
- [ ] Nanite can list mux sessions, attach to a running one, stream output, send input, and detach without killing it.
- [ ] Clockwork can dispatch a task that launches a mux session, inspect state, and read events for it.
- [ ] At least one API-backed provider (Anthropic SDK or OpenAI SDK) is implemented and shares the session model with the CLI provider.
- [ ] Checkpoint create → resume path works: a running session can be checkpointed; a new session can be launched from a checkpoint for the same LogicalAgent.
- [ ] Broker supports request → response envelopes correlated by ID; workflow-scoped session groups are first-class in storage and the API.
- [ ] Event subscription works over the local API for external clients (not just internal).

## Motivation

Context-pack §03 calls v0.0.3 the "integration foundation": the first version where external systems can actually depend on Agent Mux. Context-pack §04 Use Cases 1–3 (interactive attached session, detached background task, multiplexor pattern) all need the pieces that land here. Context-pack §08 fully specifies the broker semantics (request / response / notice / escalation / handoff / status update).

The architectural payoff: after v0.0.3, Nanite stops being a standalone console and becomes a proper client of the runtime. Clockwork stops reaching into filesystem state and talks to a real service. The runtime is no longer CLI-only. Checkpointing proves the durability story. The broker proves the multi-session coordination story.

## Scope

### In
- Nanite adapter: discovery, attach, input round-trip.
- Clockwork adapter: launch, status, event tap, dispatch patterns.
- First concrete API-backed provider implementation (not a stub).
- Checkpoint create/resume end-to-end, including wiring into session stop/handoff.
- Broker request/reply semantics + correlation IDs + workflow-scoped groups.

### Out (deferred to v0.1+)
- Hot/cold lifecycle policy; planner/operator logical-agents (v0.1).
- Stalled session detection, escalation conditions (v0.1).
- Memory scopes integration with Vanta (v0.1).
- Agent Ops asset resolution (v0.2).
- Rich TUI/GUI (v0.3+).

## Review / readiness notes

- **Nanite API shape is unknown to this repo.** Sprint v003-01 needs to start with a discovery pass against the real Nanite codebase — this epic's readiness depends on that. Capture a readiness gap there if the Nanite repo isn't accessible to the execution agent.
- **Clockwork integration depth:** "dispatches through mux API" could mean anything from "Clockwork fires a launch API call" to "full operational-agent orchestration." v0.0.3 is the minimum: a dispatch path and an inspection path. Escalation and queue review hooks are v0.1.
- **Provider SDK pick:** Anthropic vs OpenAI for the first API provider. Anthropic is the closer analogue to the existing `claude-code` CLI (same vendor, same model family) so reuse is easier. Decide as part of Sprint v003-03's first task.
- **Checkpoint payload schema is intentionally loose in v0.0.2.** v0.0.3 has to pin it down enough for a resume path to actually work. Expect that sprint to produce an ADR.
- **Broker correlation model:** context-pack §08 lists message types (request / response / notice / escalation / handoff / status update) but doesn't pin wire schemas. v003-05 needs to choose a correlation-ID scheme (UUID, monotonic, or something else) and document it.
- **Sprint depth is intentionally thinner than v0.0.2.** Expect 2–4 tasks per sprint, with placeholders where real integration work is required against external repos. Readiness review will refine per sprint when those repos are in hand.
