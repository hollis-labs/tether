- An `identity.mcp_grants` entry may now name one catalog agent with `agent: <id>` (CW-20261112-0082). A service or interactive principal bound this way carries that agent's machine designation on the daemon MCP transport: its calls to a machine-changing upstream it is granted are read-write only when the agent has `machine_authority: true` and `machine_access: read-write`. Without `agent` nothing changes, the operator credential stays read-only there, the binding grants no upstream, scope or session policy, and an unknown agent id fails grant validation. First user: the sysadmin Cerberus agent, which Tether does not launch and so has no session credential.
