- A worker start no longer stalls on dead session hosts (CW-20261114-0056): restore classifies each dir under
  `hosts/` first (no `meta.json`, no launch descriptor, or a control socket that is missing or refuses) and reads a
  session's output only after its shim accepts the controller connection. Before, every dead dir's whole
  `output.jsonl` was decoded first, so a pile of finished sessions outran outpost's plugin init deadline. Dead dirs
  idle 24h are moved, never deleted, to `hosts-dead/<YYYYMMDD>/` (kept if their recorded host pid is alive). The
  worker logs `restore: live= dead_skipped= pruned= failed=`, and its hello carries the counts (`restore`), which the
  hub logs.
