- Typed asks and replies (CW-20261117-0003): the envelope has a `request` kind ("do X and
  report back") with a required `deliverable` and no options, `subject` is required on a
  request (question, decision and approval_request default it to the body's first line),
  and replies may carry `status` (done/declined/blocked) and `evidence`. A typed request
  triages as action. A reply's `to` and `awaiting` default to the parent's sender (untyped
  replies get `metadata.awaiting`), and a plain reply no longer holds the asker's Stop gate.
  New MCP tools `tether_ask` and `tether_reply` build and validate the envelope; the wake
  turn for a typed ask shows the sender handle, subject and deliverable.
