- CW-20261017-0036: The worker's `mcp-http-relay` now starts a replacement hub MCP session when the hub answers `404 mcp_session_not_found`, then retries the request once. The hub drops an agent's MCP view when it sits idle (observed at roughly fifteen minutes; the exact trigger is not established) and on restart, and the relay used to keep sending the dead session id, so a chat agent that went quiet for that long lost every hub tool until it was relaunched. The replacement replays the agent's own initialize under a relay-internal id and never shows the handshake to the agent; concurrent requests share one replacement, and a hub that keeps answering 404 gets one attempt per request, not a loop.
