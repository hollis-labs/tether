# Migrations

One goose migration set per dialect, embedded by `migrations.go` from `sqlite/` and `postgres/` and registered with `database.UseMigrationFS`. Both directories hold the same versions; `TestMigrationParity` fails otherwise.

- `sqlite/00001_schema.sql` is the squashed schema of the old store at its migration 0101. It is generated by `go test ./internal/migrate -run TestSchemaEqualsOld -update` and proven equal to the old migrations by the same test. Do not edit it by hand.
- `postgres/00001_schema.sql` is the same schema for Postgres, hand-maintained, under the type and construct rules in its header. `TestPostgresSchemaMatchesSQLite` proves its tables, columns, keys, indexes, checks and triggers match the SQLite set, and `TestTriggerParity` runs the triggers on both. Both need `SUBSTRATE_TEST_POSTGRES_DSN`; without it they skip with a notice.
- `00002_messages_seq.sql` adds `messages.seq`, the explicit message sequence that replaces the implicit `rowid` as the mailbox watch cursor. `messages` is therefore a transform table in `TestSchemaEqualsOld`.
- Later schema changes are `00003` onwards, one file per dialect with the same version. They are never edits to an applied file.
- No per-version `ALTER` ladders from the old tree.
